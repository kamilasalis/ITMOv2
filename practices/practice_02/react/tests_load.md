Обоснование: правило `API-1` (diff > 20 000 отклоняется с HTTP 413) и валидация длины diff до передачи в `ReviewService` | При падении производительности из-за парсинга больших тел запросов сервис сохраняет возврат HTTP 413 без вызова LLM и не падает с OOM | CPU < 60%, RAM стабильна (нет накопления полезной нагрузки в памяти, предотвращение OOM) | Сводка k6/locust: `100% status == 413, p99 < 50ms, LLM mock call count == 0` |

На данном этапе MVP сервис не рассчитан на публичную неконтролируемую нагрузку во внешний LLM, так как узким местом является внешний API LLM с жесткими лимитами RPS и стоимостью токенов. Все нагрузочные тесты сервиса выполняются исключительно с моком LLM, а допустимый предел времени ответа строго опирается на таймаут REL-1 (10 секунд + допуск 0.5с на оверхед сервиса по прецеденту tests_integration.md) и лимит длины API-1 (20 000 символов).
