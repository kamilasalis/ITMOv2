## 2. Предложение общего контракта

### 2.1 Имя игрока

Одна функция нормализации, одинаковая на клиенте и на сервере:

**Пробельный символ** — символ, для которого в Python `str.isspace()` истинно (сервер использует
`" ".join(name.split())`); клиент повторяет ровно этот набор, а не `\s` из JS.

1. Обрезать пробельные символы по краям.
2. Заменить каждую серию пробельных символов внутри на один пробел.
3. Проверить длину: 1–20 **кодовых точек Unicode**. Других ограничений на символы нет
   (решение В4): допустимы любые символы — буквы любых алфавитов, цифры, эмодзи, знаки.
   Табуляция и перевод строки — пробельные символы, поэтому шаг 2 превращает их в пробел.

| Где | Когда | Что делает |
|-----|-------|------------|
| Клиент | При нажатии «Начать заезд!» | Нормализует оба имени, записывает результат обратно в поля и дальше везде (HUD, «Финиш», запрос) использует нормализованное имя |
| Клиент | При вводе | Счётчик «N/20» считает кодовые точки, ввод сверх 20 не принимается |
| Сервер | При POST | Повторяет нормализацию и проверку длины; нарушение → 422 |

Ошибки имени на клиенте, все блокируют старт:

| Условие | Текст |
|---------|-------|
| Пустое после нормализации | «Введите имя» |
| Совпадает с именем второго игрока по ключу (см. ниже) | «Имена игроков должны различаться» |

**Ключ имени** (по нему считаются «одинаковые имена» и «один рекорд»): нормализованное имя
в нижнем регистре (`casefold`) — решение В1: регистр не учитывается. «Камила», «КАМИЛА» и
«камила» — один игрок и одна строка таблицы. В таблице показывается имя в том написании, в
котором оно было при установке текущего рекорда.
Сервер сравнивает через `casefold()`, клиент — через эквивалент: `toLowerCase()` →
`toUpperCase()` → `toLowerCase()`, участки с «ı» (U+0131) не меняются. Проверено на всех
символах Unicode: какие имена считаются одинаковыми, на клиенте и сервере совпадает
(в т. ч. «ß»/«SS», «ς»/«σ»).

### 2.2 Время

- Единица на проводе — **целые миллисекунды** (`int`).
- Форматирование — только на клиенте: `ММ:СС.сс`, сотые **отбрасываются**:
  `cs = floor(ms / 10) % 100`. Максимум отображения — `99:59.99`.
- Допустимый диапазон сохранения — 3 000 – 5 999 999 мс. Клиент **не отправляет** время
  вне диапазона и сразу показывает «Результат не сохранён: время вне допустимого диапазона»
  (решение В6).

### 2.3 Состав таблицы рекордов (решение В7)

- **Хранение.** Сервер хранит лучший результат каждого имени, **без лимита на число имён**
  и без вытеснения: каждый успешный `POST` сохраняется. Лимит 1000 из спеки логики (L FR-012)
  и сокращение «10 → 5» **отменены**. После сохранения UI просто обновляет таблицу.
- **Топ-10.** Таблица на экране показывает 10 лучших имён (места 1–10).
- **Последний результат.** Сервер дополнительно хранит последний сохранённый результат гонки —
  один на всех игроков и все устройства. Он перезаписывается при каждом успешном
  `POST /race-results` и переживает перезапуск сервера.
- **Отдельная строка.** Под топ-10, через разделитель, показывается строка «Последняя гонка»,
  **только если** имени из последнего результата нет в топ-10. Если оно в топ-10 — отдельной
  строки нет, а его строка в таблице подсвечивается.
- Содержимое отдельной строки: место имени в общей таблице, имя, **время этой гонки**
  (не лучшее время имени).
- Строка видна на обоих экранах, где есть таблица («Выбор» и «Финиш»). На «Финише» это обычно
  только что завершённая гонка, но если за это время финишировал кто-то на другом устройстве —
  его гонка.

Пример (в хранилище 14 имён):

| Место | Имя | Время |
|-------|-----|-------|
| 1 | Боря | 00:40.00 |
| … | … | … |
| 10 | Вика | 00:52.10 |
| *Последняя гонка* | | |
| 13 | Камила | 00:58.73 |

### 2.4 API

Базовый адрес — тот же, что у существующих вызовов (`http://localhost:8000`), вынесен в одну
константу на фронтенде.

#### `POST /race-results` — сохранить время победителя

Запрос (`extra="forbid"`):

```json
{ "name": "Камила", "lap_time_ms": 65400 }
```

Ответ `201`:

```json
{
  "name": "Камила",
  "lap_time_ms": 65400,
  "best_time_ms": 61230,
  "is_new_record": false,
  "place": 4
}
```

| Поле | Тип | Смысл для UI |
|------|-----|--------------|
| `name` | string | Нормализованное имя — по нему UI ищет строку для подсветки |
| `lap_time_ms` | int | Время этой гонки (эхо) |
| `best_time_ms` | int | Рекорд имени после записи |
| `is_new_record` | bool | `true` → «Новый рекорд!» (в том числе первый результат имени) |
| `place` | int | Место имени после записи (всегда есть — лимита нет, см. 2.3) |

#### `GET /leaderboard?limit=10` — таблица

Ответ `200`:

```json
{
  "entries": [
    { "place": 1, "name": "Боря", "best_time_ms": 40000, "achieved_at": "2026-10-28T10:00:00Z" }
  ],
  "total": 14,
  "last_result": {
    "name": "Камила",
    "lap_time_ms": 58730,
    "place": 13,
    "finished_at": "2026-10-28T12:30:00Z"
  }
}
```

| Поле `last_result` | Тип | Смысл |
|--------------------|-----|-------|
| (весь объект) | object \| null | Последний сохранённый результат на сервере; `null`, пока гонок не было |
| `name` | string | Нормализованное имя |
| `lap_time_ms` | int | Время именно этой гонки |
| `place` | int | Текущее место имени по лучшему времени |
| `finished_at` | string | Момент сохранения, UTC, ISO 8601 |

Правило показа для UI: отдельная строка видна, если `last_result != null` и
`last_result.place > entries.length`.

`limit` — 1–50, по умолчанию 10. Пустое хранилище → `{"entries": [], "total": 0, "last_result": null}`.
Места при равном времени (решение В2): `1, 2, 3` — выше тот, у кого `achieved_at` раньше;
номера мест не повторяются.

### 2.5 Ошибки: код → реакция UI

| Ответ | Класс | Таблица на «Выборе» / «Финише» | Сохранение на «Финише» |
|-------|-------|--------------------------------|------------------------|
| Нет ответа / сетевая ошибка / таймаут **5 с** | повторяемая | «Не удалось загрузить рекорды» + «Повторить» | «Не удалось сохранить результат» + «Повторить» |

Ни одна ошибка не блокирует выбор машинок, старт и «Новую игру».

### 2.6 Последовательность вызовов

```
Экран «Выбор» открыт ─────────► GET /leaderboard            (загрузка → данные | пусто | ошибка)
«Повторить» в таблице ────────► GET /leaderboard

«Начать заезд!» ──► проверка имён на клиенте ──► POST /select-car ×2 (как сейчас) ──► «Отсчёт»

Экран «Финиш» открыт:
  1. POST /race-results {имя победителя, его время}   статус: «Сохраняем результат…»
  2. после ответа POST (успех ИЛИ ошибка) ──► GET /leaderboard
     - POST 201: подсветить строку с name == ответ.name, если она в entries и is_new_record
     - POST ошибка: таблица без новой гонки
  «Повторить» сохранения ──► шаг 1 + шаг 2 (повтор безопасен: L FR-010)

«Новая игра» во время запроса ──► ответ игнорируется (запрос отменяется), на «Выборе» —
                                    свежий GET /leaderboard
```

### 2.7 Таймер: состояния

| Состояние | Экран | Что видно | Вход | Выход |
|-----------|-------|-----------|------|-------|
| `idle` | «Выбор» | ничего | открытие сайта, «Новая игра», «Назад к выбору» | «Начать заезд!» |
| `countdown` | «Отсчёт» | ничего, время не идёт | старт отсчёта | отсчёт = 0 |
| `running` | «Гонка» | `ММ:СС.сс` в HUD, растёт от `00:00.00`, упирается в `99:59.99` | отсчёт = 0 — момент старта по монотонным часам | финиш первой машинки → `finished`; ошибка 3D → `aborted` |
| `finished` | «Финиш» | «Время круга: ММ:СС.сс» победителя | финиш | «Новая игра» → `idle` |
| `aborted` | «Гонка» с ошибкой 3D | ничего; результат не отправляется | ошибка 3D | «Назад к выбору» → `idle` |

Правила:

- Время на «Финише» и `lap_time_ms` в POST — одно и то же значение.
- Одновременный финиш в одном кадре (решение В3, согласовано человеком 2026-10-28 по
  Принципу II): победитель выбирается **случайно** с вероятностью 50/50; повторная запись
  победителя в том же кадре невозможна. На «Финише» и в POST — выбранный победитель; время у обоих
  одинаковое (L US1-5). Для тестов источник случайности должен подменяться.
- Время скрытой вкладки входит во время (часы монотонные); после возврата таймер скачком
  показывает актуальное значение.
- Прерывания гонки кнопкой «Новая игра» на экране «Гонка» нет; единственное прерывание —
  ошибка 3D (`aborted`). Упоминание «Новой игры» в L US1-6 / L FR-004 убрать.
