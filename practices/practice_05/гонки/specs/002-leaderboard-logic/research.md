# Research: Таблица рекордов гонки (логика)

В Technical Context не было пунктов NEEDS CLARIFICATION; ниже — решения по способу реализации.

## R1. Формат JSON-файла

- **Decision**: один объект с версией формата, словарём рекордов по ключу имени и последним
  результатом (см. [data-model.md](data-model.md)).
- **Rationale**: поиск рекорда по ключу — O(1); версия позволяет отличить «чужой» или старый файл
  от повреждённого; всё состояние читается и пишется целиком одним `json.load`/`json.dump`.
- **Alternatives considered**: JSON Lines с историей заездов — спека не требует истории, файл рос
  бы без ограничений; SQLite — по сути новая технология хранения, пользователь выбрал JSON.

## R2. Атомарная запись

- **Decision**: писать во временный файл в той же папке (`tempfile.NamedTemporaryFile(dir=...,
  delete=False)`), `flush` + `os.fsync`, затем `os.replace(tmp, path)`; при исключении временный
  файл удаляется.
- **Rationale**: `os.replace` атомарен в пределах одной файловой системы — после сбоя на диске
  либо старый, либо новый файл целиком (FR-015).
- **Alternatives considered**: запись поверх файла (`open("w")`) — при сбое остаётся обрезанный
  файл; бэкап-копия — сложнее и не нужна при атомарной замене.

## R3. Одновременные запросы

- **Decision**: `threading.Lock` в `LeaderboardStore`; весь цикл «прочитать → изменить → записать»
  и чтение для GET выполняются под блокировкой. Эндпоинты — обычные `def`, FastAPI выполняет их в
  пуле потоков.
- **Rationale**: в одном процессе блокировка исключает потерю записей (US4-11) без новых
  зависимостей.
- **Alternatives considered**: `fcntl.flock` — нужен только при нескольких процессах, не работает
  на Windows; `asyncio.Lock` — потребовал бы асинхронного файлового ввода-вывода.

## R4. Повреждённый и отсутствующий файл

- **Decision**: нет файла → пустое состояние, файл создаётся при первой успешной записи.
  `json.JSONDecodeError`, `UnicodeDecodeError`, неверная структура или неизвестная `version` →
  `StorageError`; `OSError` при чтении или записи → `StorageError`. Эндпоинты превращают
  `StorageError` в 503 `{"detail": "Хранилище рекордов недоступно"}`. При повреждённом файле POST
  падает на чтении, до записи, поэтому файл остаётся нетронутым (FR-016).
- **Rationale**: молча начинать с пустой таблицы — значит стереть общие рекорды при следующей
  записи.
- **Alternatives considered**: автоматически переименовывать повреждённый файл и начинать заново —
  скрывает потерю данных, решение о восстановлении должен принимать человек.

## R5. Нормализация имени и ключ

- **Decision**: `" ".join(name.split())` — `str.split()` без аргументов делит по любым пробельным
  символам Unicode (пробел, `\t`, `\n`, неразрывный пробел…), отбрасывая края; длина — `len()`
  (кодовые точки), 1–20. Ключ — `normalized.casefold()`. Реализуется `field_validator` в модели
  `RaceResult`.
- **Rationale**: одна строка кода точно повторяет шаги 1–2 contract.md 2.1; `len()` в Python
  считает кодовые точки, как требует контракт; `casefold` — как указано в решении В1.
- **Alternatives considered**: регулярное выражение `\s+` — то же самое, длиннее; `lower()` —
  неверно для некоторых алфавитов (например, немецкое «ß»).

## R6. Один процесс сервера

- **Decision**: план рассчитан на один процесс uvicorn (так проект запускается сейчас: без
  `--workers`). Это записано в Assumptions плана и в quickstart.
- **Rationale**: блокировка из R3 работает в пределах процесса.
- **Alternatives considered**: межпроцессная блокировка — будет нужна, если когда-нибудь запускать
  несколько воркеров; тогда это отдельное решение человека.

## R7. Строгие типы и время

- **Decision**: `lap_time_ms: int = Field(strict=True, ge=3000, le=5_999_999)` — строка `"41250"`,
  дробное `41250.5` и `true` отклоняются (422). Время в ответах — UTC в ISO 8601 с суффиксом `Z`.
  Часы (`now`) передаются в `LeaderboardStore` параметром, чтобы тесты задавали время.
- **Rationale**: без `strict` Pydantic превращает `"41250"` в число и нарушает US4-4; подменяемые
  часы нужны для US2-4 (равное время не меняет `achieved_at`) и для порядка при равенстве (В2).
- **Alternatives considered**: `StrictInt` из `pydantic` — то же самое, но без ограничений диапазона
  в одном месте.

## R8. Ранжирование

- **Decision**: сортировка по `(best_time_ms, achieved_at, key)`, место = индекс + 1. Ключ — третий
  критерий только для детерминированности, если два рекорда установлены в одну и ту же микросекунду.
  `last_result.place` вычисляется при каждом GET по текущей таблице.
- **Rationale**: прямо реализует В2 (места не повторяются, раньше установленный выше); пересчёт при
  чтении не хранит устаревшее место.
- **Alternatives considered**: хранить место в файле — его пришлось бы пересчитывать при каждой
  записи у всех имён.

## R9. Внедрение хранилища в эндпоинты

- **Decision**: функция-зависимость `get_store()` возвращает модульный `LeaderboardStore` для
  `backend/leaderboard.json`; тесты подменяют её через `app.dependency_overrides` на хранилище в
  `tmp_path`.
- **Rationale**: штатный механизм FastAPI, тесты не трогают реальный файл и не зависят друг от друга.
- **Alternatives considered**: переменная окружения с путём — меняет глобальное состояние, неудобно
  в тестах; monkeypatch модульной константы — работает, но хрупко.
