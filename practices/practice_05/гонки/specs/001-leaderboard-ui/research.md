# Research: Таблица рекордов гонки (UI)

Все неизвестные из Technical Context закрыты. Источники решений: [spec.md](spec.md),
[specs/contract.md](../contract.md), текущий код `frontend/src/App.vue` и `backend/app/`.

## R1. Часы таймера и время круга

- **Decision**: `performance.now()` — момент старта фиксируется, когда отсчёт дошёл до 0, перед
  первым вызовом `runGameLoop`. В начале каждого кадра берётся одно значение `now`; таймер на
  экране = `now − start`; время круга = `Math.round(now − start)` того кадра, в котором
  зафиксирован финиш.
- **Rationale**: монотонные часы; одно значение на кадр даёт одинаковое время обеим машинкам при
  финише в одном кадре (L US1-5); время скрытой вкладки входит в замер (spec US2-8), т. к.
  `performance.now()` не останавливается, хотя `requestAnimationFrame` стоит.
- **Alternatives**: `Date.now()` — не монотонные (перевод часов); счётчик кадров — зависит от FPS
  и останавливается в скрытой вкладке.

## R2. Формат времени

- **Decision**: `formatTime(ms)`: `ms` ограничивается `[0, 5 999 999]`; `mm = floor(ms/60000)`,
  `ss = floor(ms/1000) % 60`, `cs = floor(ms/10) % 100`, каждое с ведущим нулём → `ММ:СС.сс`.
- **Rationale**: контракт 2.2 — сотые отбрасываются; максимум «99:59.99».
- **Alternatives**: `toFixed(2)` — округляет, противоречит контракту.

## R3. Длина и нормализация имени

- **Decision**: длина — `Array.from(str).length` (кодовые точки). Ввод сверх 20 обрезается в
  обработчике `input` (`Array.from(v).slice(0, 20).join("")`), но **не** во время IME-набора
  (`compositionstart`/`compositionend`). Нормализация при «Начать заезд!»:
  `str.trim().replace(/\s+/g, " ")`; результат записывается обратно в поле. Ключ сравнения —
  `normalize(str).toLowerCase()`.
- **Rationale**: атрибут `maxlength` считает UTF-16 (эмодзи = 2) — расходится с контрактом 2.1.
  `\s` в JS покрывает пробелы, табуляцию, переводы строк, NBSP — как и нормализация на бэкенде.
  `toLowerCase()` достаточно для показа «одинаковых имён» в UI; окончательное слияние имён делает
  сервер (`casefold`).
- **Alternatives**: `maxlength` — неверная единица; `Intl.Segmenter` (графемы) — сервер считает
  кодовые точки, единицы разошлись бы.

## R4. Таймаут и классификация ошибок

- **Decision**: `fetch` с `AbortController`, таймер 5000 мс. Результат вызова — объект
  `{ ok: true, data }` или `{ ok: false, kind }`, где `kind`:
  `"retryable"` — сеть, таймаут, `503`, прочие `5xx`; `"rejected"` — `422`, `413`, прочие `4xx`;
  `"aborted"` — запрос отменён «Новой игрой» (UI его игнорирует).
- **Rationale**: контракт 2.5; `422` нельзя предлагать повторять. Отдельный `aborted` отличает
  отмену пользователем от таймаута.
- **Alternatives**: `AbortSignal.timeout(5000)` — нельзя одновременно отменить вручную без
  `AbortSignal.any` (неравномерная поддержка); исключения вместо объекта результата — сложнее
  тестировать.

## R5. Отмена устаревших ответов («Новая игра» во время сохранения)

- **Decision**: у экрана «Финиш» есть `AbortController` текущей операции; `resetGame()` вызывает
  `abort()`. Дополнительно — счётчик поколений: ответ применяется, только если его поколение
  совпадает с текущим.
- **Rationale**: spec US4-8 — ответ прерванного сохранения не показывается. Счётчик страхует от
  ответа, пришедшего между `abort()` и обработкой.

## R6. Победитель при финише в одном кадре — без изменения физики

- **Decision**: `checkLap` и `updatePhysics` не трогаются. Меняется только тело `declareWinner`:
  оно не переключает экран, а добавляет игрока в список `frameFinishers`. После
  `updatePhysics()` в `runGameLoop` вызывается `resolveFinish(now)`: если список не пуст —
  `pickWinner(frameFinishers, Math.random)` выбирает победителя (1 кандидат → он; 2 → 50/50),
  фиксируется время круга и экран переходит в «Финиш».
- **Rationale**: сейчас при одновременном финише победителя перезаписывает игрок 2 (контракт T3);
  В3 требует 50/50. Решение не меняет ни движения, ни порога круга (Принцип II). `random`
  передаётся аргументом, поэтому тестируется детерминированно.
- **Alternatives**: проверять финиш внутри `checkLap` — это правка функции правила круга.

## R7. Последовательность вызовов на «Финише»

- **Decision**: при входе в «Финиш»: если время вне `[3000, 5 999 999]` — статус
  `out_of_range`, POST не отправляется; иначе статус `saving` → `POST /race-results` → статус
  `saved | error | rejected`; **после любого исхода** — `GET /leaderboard`. «Повторить»
  повторяет оба шага.
- **Rationale**: контракт 2.6; повтор POST безопасен (L FR-010).

## R8. Правила показа таблицы

- **Decision**: чистые функции в `raceLogic.js`:
  `showLastResultRow(board) = board.last_result != null && board.last_result.place > board.entries.length`;
  подсвеченная строка — имя `last_result`, если оно в `entries`; бейдж «Новый рекорд!» — только
  на «Финише», если `saveResponse.is_new_record` и имя в `entries`. Сравнение имён — по ключу
  (`toLowerCase` нормализованного имени).
- **Rationale**: контракт 2.3–2.4; spec US3-8, US3-10..13.

## R9. Адрес API

- **Decision**: `API_BASE = "http://localhost:8000"` в `api.js`; новые вызовы используют его.
  Существующие `/select-car` в `App.vue` и `/report-error` в `ReportErrorButton.vue` не
  переписываются (вне рамок фичи).
- **Rationale**: контракт 2.4; минимальный объём правок. CORS для `:5173` уже настроен на
  бэкенде, правки бэкенда не нужны.

## R10. Тесты фронтенда

- **Decision**: `node --test` (встроен в Node 24), файлы `frontend/tests/*.test.js`, скрипт
  `npm test`. В `scripts/check.sh` не добавляются.
- **Rationale**: решение человека 2026-10-28; Принцип I — без новых пакетов (Vitest/Jest
  отклонены как новые фреймворки).
- **Последствие**: регрессия во фронтенде не делает `check.sh` красным; `npm test` нужно
  запускать вручную (шаг в [quickstart.md](quickstart.md)).
