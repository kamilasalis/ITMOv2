# Отчёт по практике 8

## Проект «Что готовим?»

Пользователь хочет решить, что приготовить из продуктов, которые есть дома. Он выбирает один или несколько приёмов пищи, продукты и размер порции. Приложение показывает до трёх меню с граммовками и шагами приготовления. В каталоге 31 рецепт на 20 продуктов. Если точного совпадения нет, интерфейс показывает ближайшие блюда и перечисляет, что нужно добавить.

## Макет и реализация

- [Интерактивный макет](menu/design.html) фиксирует согласованный сценарий и внешний вид. Его можно открыть прямо в браузере вместе с ресурсами из папки `menu`.
- [Рабочий интерфейс](menu/prototype.html) подключён к [локальному API](menu/server.cjs). При запуске напрямую из файла использует тот же [модуль каталога и подбора](menu/recipes.js). Для защиты запустите приложение командой `npm start` из `practice_08/menu` и откройте `http://127.0.0.1:4173`.
- Библиотека компонентов — Bootstrap 5.3.8. В HTML переиспользуются `btn`, `form-control` и `card`. Палитра задана CSS-переменными, общие размеры и типографика — в стилях интерфейса. Чекбоксы, радиокнопки и раскрываемые блоки рецептов управляются с клавиатуры.

Для знакомства со сценарием выберите завтрак, яйца и помидоры. Нажмите «Готовить», затем раскройте состав омлета. В режиме «Профицит» по 100 г яиц и помидоров превращаются в 115 г. Если выбрать для завтрака только яйца, выдача покажет, какие продукты нужно добавить. Пустой ответ API и сбой воспроизводятся тестами с подменой ответа. В макете доступна демонстрация повторной попытки по параметру `?preview=error`.

## Тестирование

[Клиентские тесты](menu/test/menu.test.cjs) используют Playwright. Основной тест проходит через настоящий локальный API. Остальные проверки включают обязательный ввод, поиск, сохранение выбора, Enter, задержку, пустой ответ, ошибку и повторную попытку. Во время задержки тест повторно вызывает отправку и сверяет фактическое число запросов. Формат тестовых ответов совпадает с форматом API.

[Вывод полного запуска](menu/evidence/test-run.txt). В [отдельном проверочном запуске](menu/evidence/mutation-run.txt) заменили видимый текст ошибки и убедились, что тест упал. Восстановили исходное сообщение и повторили полный прогон.

## Использование AI и правки после проверки

[Промпты для макета, реализации, тестов и иллюстраций](menu/PROMPT.md). Это сводные версии запросов по итогам последовательных правок. Исходная задача пользователя и её решения сохранились в сценарии. Codex предложил структуру каталога, подбор ближайшего блюда и автоматические проверки. ImageGen создал иллюстрации продуктов в общей палитре.

- После первого макета пользователь выбрал референсы Julienne, Maxima Therapy и Hungry Tiger. В итоговой версии первый экран заняло видео, а выбор приёмов, продуктов и порций разнесли по отдельным экранам.
- По замечанию пользователя несколько отдельных изображений блюд заменили одной непрозрачной тарелкой, которая перемещается при прокрутке. В конце поднимается пар.
- Пользователь отклонил системные эмодзи и набор Twemoji для продуктов. Их заменили рисованными иллюстрациями. На карточках приёмов пищи вместо эмодзи появились рассвет, яркий день, закат и поздний вечер.
- При проверке клиентских тестов обнаружили, что значок выбора менял доступное имя продукта. Индикатор вынесли в декоративный элемент, скрытый от программ чтения с экрана.
- При финальной проверке переименовали класс сообщений о состоянии. Он совпадал с классом Bootstrap, который делал сообщения полупрозрачными. Скриншоты и тест ошибки обновлены.
